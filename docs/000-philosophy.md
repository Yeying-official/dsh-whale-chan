# 000 理念

> 状态：WS1 起实现，WS7 补全。本文说明DSH助理的产品原则；具体设计见 [010 设计摘要](010-design.md)，安全边界见 [013 安全基线](013-security.md)。

DSH助理不是“更聪明的群机器人”，而是一个**低打扰的个人助理**：它借用主人的钉钉身份，替主人接住那些“看到了要回、但不值得立刻打断主人”的消息，并把真正需要动手的事留到主人愿意处理的时候。

## 1. 四条产品原则

| 原则     | 含义                                                                                                | 落到实现                                                                                                         |
| -------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 少打扰   | 默认只在明确提及、私聊或白名单目标中响应；静默时段、限速与防环是硬边界，不是建议                    | `@我` / 指定群 / 指定单聊三类目标；群聊默认必须 @；22:00–08:00 默认不自动回复；每会话每小时上限与最小间隔        |
| 人的批准 | AI 可以捕获任务、准备草稿、执行已批准的工作，但不能替人批准任务，也不能把“聊天里的请求”直接当成授权 | 任务只有 `awaiting-approval` 且 Approval `pending` 才能被批准；批准只在 DSH 面板；迟到批准无效；没有批准不建会话 |
| 可解释   | 每条回复与每个任务都能追溯到来源消息、决策、策略原因、批准记录与执行结果                            | Decision 记录 `intent`、`confidence`、`reason`；审计事件只放 ID 与状态；面板与审计可查                           |
| 可停止   | 暂停、关闭自动回复、拒绝/取消任务、卸载插件都是一等操作；停止后不应留下“看不见的发送者”             | 概览的暂停、`monitor.enabled`、`replyMode=off`、任务取消、单实例锁、通道 stop 顺序                               |

## 2. 自动化与人的分工

**可以自动做**：

- 读取授权范围内的新消息，去重、过滤自消息/广播/媒体；
- 判断 `chat` / `question` / `task` / `ignore`，生成回复草稿或直接发送短回复；
- 对问题类消息做有预算的联网检索，并在正文里引用来源；
- 捕获任务、生成标题与说明、在面板里等待批准；
- 执行已批准任务，把结果摘要回到原会话。

**必须留给人**：

- 批准、拒绝、取消任务；重试失败任务；
- 修改目标、人设、发送者名单与权限预设；
- 处理 `unknown` 投递、失败任务与异常账号；
- 任何不可逆、涉及付款/合同/对外承诺的动作——即使模型判断为任务，也只是“候选”，不是执行。

## 3. 取舍

- **召回 vs 噪声**：宁可漏回一条，也不在错误群里自动发言。目标白名单与“群聊必须 @”优先于覆盖率。
- **便利 vs 披露**：所有助手消息固定带 AI 角标（v1 不可关闭）。这会让对方知道是助理代回，但这是使用主人身份的底线。
- **自动 vs 安全**：静默时段、限速、防环触发时降级为 `review`（草稿），而不是硬拒绝；但 v1 没有草稿发送入口，所以最终仍需主人处理。
- **能力 vs 权限**：回复器没有 shell/文件/作业/skill；任务执行器也只有受限工具集。提示词不能改变权限。
- **本地 vs 云端**：状态与审计在本地 SQLite；分类、回复、执行所需的文本会按 DSH 的模型路由发出。插件不额外上传整库。

## 4. 不做什么

- 不做“全自动群运营”：不主动群发、不猜目标、不自动加群、不替主人做承诺。
- 不做钉钉机器人：使用 `dws` 个人授权，以主人身份发言；因此必须接受“发出去就是主人说的”这一后果。
- 不做无审计的自动化：每个任务都有批准记录，每次发送都有 Outbound 与回执状态。
- 不追求“永远在线”：单实例、可暂停、失败关闭；宁可停住，也不在授权/模板/数据库异常时猜着跑。
