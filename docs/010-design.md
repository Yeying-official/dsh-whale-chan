# 010 设计摘要

> 当前状态：设计摘要已冻结（WS0）。本文描述目标架构和硬规则；只有 WS0 骨架已经落地，其余能力尚未实现。

## 1. 产品目标

「鲸鱼酱 · 钉钉助理」是运行在 DeepSeek Harness 中的个人助理。它以本机 `dws` 的个人授权读取用户可见的钉钉消息，判断一条消息是否需要回复、补充检索或转成可执行任务，并把需要人负责的动作放回 DSH 面板处理。

目标不是把鲸鱼酱做成一个“全自动群机器人”，而是：

- **少打扰**：默认只在明确提及、私聊或白名单目标中响应；免打扰、频率上限和最小间隔是硬边界。
- **可解释**：每条回复和每个任务都能追溯到来源会话、消息、决策和批准记录。
- **可停止**：暂停监控、关闭自动回复、拒绝任务和杀死通道进程都是一等操作。
- **可恢复**：入站事件、待发消息和任务状态在本地持久化；进程重启不重复发送、不丢失待办。
- **人的批准在面板**：AI 可以捕获任务，但不能替人批准任务。

默认值决策：`monitor.quietHours.enabled = true`（本地时间 22:00–08:00），`monitor.replyDuringQuiet = false`；即默认在夜间不主动回复，但消息仍记录。没有启用目标时，监听循环只做授权与游标空转，不产生 Decision、Effect 或发送。

## 2. 通道：dws 个人授权

通道使用本机 `dws` 的个人授权，而不是钉钉机器人。个人授权决定了助手能看到的口径：当前登录用户可见的会话与消息。因此产品必须始终把“用户自己的授权”与“对外发言”区分开，不能把个人身份当成机器人身份。

### 2.1 事件键

WS0 不订阅任何事件。WS1 先通过 `dws` 的类型、help 和 schema 实测确认事件键，再把事件键冻结进通道适配器；本文不猜测具体字符串。设计上只接受三类经实测确认的事件：

- 个人消息事件（新消息与可恢复的补收游标）；
- 提及事件（群聊中 @ 当前用户）；
- 会话或成员变化事件（用于更新 Thread 标签，不用于自动发言）。

适配器必须保存 `eventId` 或等价的稳定幂等键；没有稳定键的事件不得进入决策层。目标列表为空时，监听循环只做授权与游标空转，不产生 Decision、Effect 或任何发送副作用。

### 2.2 发送参数

发送只经 `channel.sender` / `sender` 层，入参必须显式包含：

- `kind`（`at-me`、`group` 或 `dm`）与目标 ID；
- 纯文本或受支持的消息内容；
- 对应的 `threadKey`、来源消息和 Outbox 记录 ID；
- 固定的 AI 标识（由代码追加，不由模型生成）；
- 客户端生成的请求 ID，用于恢复时去重。

禁止默认群发、禁止隐式 @所有人、禁止进入发送层的“自由文本命令拼接”。所有目标先经过设置白名单与授权检查。

### 2.3 进程与信号

`src/channel` 是唯一允许启动 `dws` 子进程的层。通道在 Runtime 停止时：

1. 先停止接收新事件；
2. 向子进程发送 SIGTERM，等待有限宽限期；
3. 仍未退出则强制结束；
4. 记录退出状态，保留游标，交由下一次启动恢复。

不得在卸载后留下孤儿进程。Windows 上的子进程终止语义在实现时另做实测，并记录到 spike/实现说明中。

### 2.4 显式 ID

入站事件 ID、Thread 键、任务 ID、Approval ID、Outbox ID 都必须是显式值，不能依赖数组下标、时间戳或进程内自增。跨重启的恢复、审计和幂等全部以这些 ID 为准。

## 3. 分层与依赖规则

| 层             | 职责                                              | 允许依赖                              | 禁止                                  |
| -------------- | ------------------------------------------------- | ------------------------------------- | ------------------------------------- |
| `src/shared`   | 设置 schema、字段表、API 合约、视图模型、边界常量 | 浏览器和 Node 都能用的纯模块          | Node 内置模块、宿主实现               |
| `src/core`     | Thread、Decision、Task、Approval 等领域规则       | 仅本层                                | I/O、环境变量、定时器、任何其他项目层 |
| `src/app`      | 组合 Runtime、HTTP、持久化、Outbox、Passes        | core、shared、端口接口                | 直接启动 dws；直接向钉钉发送          |
| `src/channel`  | dws 子进程、事件解码、发送参数                    | shared、app 提供的端口                | 领域决策；绕过 sender                 |
| `src/sender`   | 唯一发送出口与发送幂等                            | shared、channel 端口                  | 读取业务状态；生成决策                |
| `src/executor` | DSH 会话、工作区、权限预设与任务执行              | app/core 提供的端口                   | 自己发钉钉消息                        |
| `src/client`   | Web 面板                                          | shared 的类型与字段表、DSH 客户端服务 | 宿主实现、Node 内置模块、发送层       |

WS0 的目录和契约测试保证：`core` 没有 import，`shared` 不 import Node 内置模块，`client` 不 import `app`、`channel`、`sender`、`executor` 或 `core`。以后新增跨层调用必须通过 app 暴露的窄接口，不允许用“图方便”的相对导入破坏方向。

## 4. 领域模型与任务状态机

### 4.1 概念

- **Thread**：一个可追踪的会话，键由通道类型和目标 ID 确定；保存最近消息时间、标签和任务引用。
- **Message**：入站或出站消息；保存稳定消息 ID、发送者、正文、时间和方向。
- **Decision**：对一条消息的纯判断结果（忽略、回复、捕获任务、检索），带原因和时间。
- **Task**：从消息捕获的可执行单元；记录来源 Thread、标题、状态、时间和 Approval 引用。
- **Approval**：人对待执行任务的明确授权；有有效期，只有 `approved` 且未过期的 Approval 才能放行执行。
- **Assignment**：已批准任务到执行器 Session 的派工记录；记录会话 ID、状态和时间。

### 4.2 任务状态机

```text
captured
  └─ capture-task ─> awaiting-approval
                        ├─ approve ─> queued ─> running ─> succeeded
                        │                         └─────> failed
                        ├─ reject ─> rejected
                        └─ ttl ───> expired
queued / running ── cancel ─> cancelled
```

硬规则：

- `awaiting-approval` 是执行前唯一可被批准的入口。
- 没有 `Approval.status === 'approved'` 的任务不得进入 `queued`，更不得进入 `running`。
- Approval 过期后，迟到批准无效，任务必须转 `expired`，不得“补执行”。
- 拒绝、取消、失败都要写审计；恢复时不得把已终止任务重新启动。

## 5. Effects、Passes 与 Outbox

领域判断与副作用分离：

- **Pass**：可重入的纯阶段推进，读取快照，产出零个或多个 Effect；同一输入重复运行结果一致。
- **Effect**：要提交的副作用意图，如“发送回复”“派工任务”“写通知”，携带显式幂等键。
- **Outbox**：唯一的外部提交边界。先持久化 Effect，再执行；执行结果回写同一 Outbox 记录。

发送成功以渠道返回的显式消息 ID（或等价确认）为准。Outbox 允许至少一次投递，但同一幂等键最多产生一条外部消息；恢复时先查 Outbox 与渠道确认，再决定重发还是标记完成。任何“先发送、后落库”的实现都视为违反设计。

## 6. 人设与检索

人设字段（`persona`）是唯一的人设来源：名字、身份、语气、语言、签名、规则、背景知识、示例和长度上限。回复提示词由这些字段组装；规则不得覆盖下面的安全约束。

检索（`research`）通过 DSH 的 `web` 能力完成，不自行拼接外部搜索 API。默认只在明确问题中检索，限制结果数、超时和缓存，并保留引用；检索失败时按“无检索结果”回复，不阻塞任务流。

## 7. 批准只在面板

批准、拒绝和取消只在 DSH Web 面板的 `whale-chan` 页面完成。钉钉侧只显示“等待批准”的状态，不提供批准按钮，也不通过聊天文本改变 Approval。

管理 API 的批准/拒绝端点必须校验：任务存在、Approval 属于该任务、状态为 `pending`、未过期、请求来自同源面板。批准成功后写入 Decision/审计，再以 Outbox 推进 `queued`；不允许 HTTP handler 直接调用执行器。

## 8. 安全

- **AI 角标固定**：发送层在所有助手消息上追加固定标识；模型输出不能移除或伪造它。
- **防回环**：只处理确认来自人的消息；忽略机器人、自己、系统通知和明显的转发/广播；发送后不把回显当成新输入。
- **限流**：按会话的每小时上限、最小间隔、目标上限和任务并发上限共同限制；触发限制时记录并停止，而不是排队无限增长。
- **日志脱敏**：默认不记录 token、cookie、手机号、完整消息正文；调试正文必须显式打开，并在审计中提示。凭证永远不进入仓库、设置快照或普通日志。
- **最小权限**：任务使用配置的权限预设，危险预设必须由人显式选择；工作区根目录和可执行路径受白名单约束。
- **失败关闭**：dws 不可用、授权过期、Schema 变化、未知事件或 Outbox 不一致时停止发送并进入可观察错误态，不做猜测性降级。

## 9. 测试群与真机护栏

真机测试只在 `AI工程师孵化中心` 测试群进行，按 T0–T3 逐级放行：

- **T0**：只读检查 `dws` 版本与 `auth status` 的布尔结果，不订阅、不发送。
- **T1**：在测试群开启事件接收，断网/重启验证游标、去重和恢复，不自动回复。
- **T2**：只发草稿或面板确认后的回复，验证 AI 角标、限流和防回环。
- **T3**：端到端任务，从捕获到面板批准、执行、回传；失败路径必须先行演练。

护栏：只允许测试群目标、默认提及限制、自动回复默认关闭、演练模式默认开启；每次放量前检查目标 ID 和回复上限；出现非测试群消息立即停止通道并保留审计。WS0 不执行任何一步真机发送或订阅。

## 10. 版本、PR 与文档同步

- 包版本遵循 SemVer；WS0 为 `0.1.0-dev.0`，兼容的 DSH 版本写入 `dsh.compatibility.dshReleases`。
- 分支使用 `feat/...`，提交遵循 Conventional Commits；PR 模板要求目标、方案、影响面、测试证据、风险和文档同步。
- 任何共享合约变化必须同步：`settings.ts`、`fields.ts`、`api.ts`、`models.ts`、locale、`docs/011-settings-contract.md` 和契约测试。
- 合并前必须有 `pnpm check`、`node scripts/check-pack.mjs` 和干净工作区；合并与安装到 profile 由人工执行，不由实现代理自动完成。
