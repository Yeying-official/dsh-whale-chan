## 1. 范围与实现

WS14 解决两件事：

1. **归档一个目标对应工作区的全部会话**：`POST targets/:id/archive-sessions`，body `{ stopActivity? }`；候选为 registry 同路径 `sessionIds`、sessionPersistence header.cwd 同路径 id、当前 replier 的并集；结果按 archived / alreadyArchived / refused / missing / failed 分区；不删目录、不删会话日志、不 unarchive；归档后若当前 replier 在归档集内则轮换 generation。
2. **归档或手动移除工作区后保持可用**：`ConversationSessions.prepareReply` 在每轮消息前 mkdir、registry resolve/create（缺失才建、绝不改标题）、重建记录时 best-effort attach 旧会话，归档则递增 generation；`SessionModel` 每轮预检，id 变化则取消旧会话并 fresh 新建；任务侧 `ensureWorkspace` + `ensureWorkerSessionId`。

设计细节以代码为准，本报告只给验证结论；不把实现描述当作验收证据。

### 8.1 已写明的限制（保持已知、文档化、非阻塞）

以下限制已在 012、CHANGELOG `Known limitations`、PR 与 compatibility 写明；P2-6 保持“已知、文档化、非阻塞”。

1. 不删除目录、文件、会话日志；归档只是从可见面隐藏。
2. 不提供 unarchive；在 DSH 手动 unarchive 不会回滚 generation，旧回复上下文不会自动恢复。
3. generation 只增；每归档一次当前 replier 就前进一代。
4. 候选上限 500；>500 时只处理排序后的前缀，**重复调用不会推进尾部**（已归档会话仍占名额）。
5. 重复 target id 时只处理首行（`find` 语义）。
6. 归档并集包含主人手建会话、任务会话，以及别目标显式批准到本目录的会话；这是设计取舍。
7. `stopActivity: true` 会取消运行中的回复和任务，任务可能失败；默认 false 时活动会话被 refused。
8. 本轮未跑真机；`blocked` 重试与 stopActivity 的真实取消未在活体 DSH 验证。
