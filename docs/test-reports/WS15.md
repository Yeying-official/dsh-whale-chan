## 4. 关键行为的测试断言（摘要）

- **D1 发现**：`discoverPeers('张三')` 只调用 `contact user search --query 张三 --format json`；候选是 `{kind:'dm', id:'<userId>'}`；只有 open id 时是 `open:<id>`；空查询抛 `invalid-target`；`chat-list` 不被调用。
- **D2 出站**：`threadTarget` 对已知 open id 输出 `open:<id>`；`threadKeyOf` 把它还原成 `dm:<id>`；用 `userId`/裸 open id/`open:<id>` 三种写法各写一条 outbound，`recentOutboundTexts` 都能取到。
- **D3 拒绝**：stdout 上的一行 `{"error":{...}}` 不会增加 `malformed`；`lastError` 是脱敏单行；`retry_after_seconds=120` 时延迟取 120 s（受上限约束）；连续 3 次无 retry 提示后不再安排重启，`state=failed`。
- **D4 id**：`cid...=` 与 `open:cid...=` 都返回 `{valid:false}` 且不发 `--dry-run`；`open:<openId>` 与裸 `userId` 分别映射到两个 flag。
- **D5/D6 策略**：目标行 `mentionOnly=true`、全局 false 时，未 @ 的群消息 `not_addressed`；全局 true、行内 false 同样拦截；两者都 false 时放行；at-me 行与群行同订一群时，普通消息用群行、@ 消息用 at-me 行。
- **D7 面板**：`GET channel` 成功时渲染状态徽标与 `lastError`；`GET channel` 失败时显示「订阅状态不可用」且保存/校验仍可用；`at-me`/`dm` 行的「仅 @」开关 disabled。

## 5. 真机未覆盖项（必须补验）

以下每一项都在本轮**没有**真实证据，发布前不要写成“已验证”：

1. **`at-me` + `group` 同群去重**：普通群消息按群行策略、@ 消息按 at-me 行策略；两条订阅同时存在时 `dws` 侧是否会重复投递。
2. **单聊订阅**：`contact user search` 找到真实联系人 → 保存 `userId` 或 `open:<id>` → `GET channel` 显示 `ready`。
3. **单聊出站**：收到单聊消息后回复，确认发送走 `--open-dingtalk-id`，`dws` 不报“用户无法解析”，消息出现在对方会话。
4. **服务端拒绝的真实形态**：故意填一个服务端不认的 id，确认 stdout 的 `{"error":{…}}` 被识别、`GET channel.lastError` 与面板一致、3 次后停止重启。
5. **`retry_after_seconds` 的真实取值**：服务端是否真的返回该字段、单位是否秒。
6. **`contact user search` 的边界**：同名/重名联系人、跨部门、分页；`nick` 与 `name` 不一致时的候选排序。
7. **`o2o` 事件键在登录态下能否 ready**（本轮只有 `at-me` 曾以 `--ephemeral` 探测到 ready 的记录）。
8. **旧配置升级**：把一条 `cid…=` 形态的旧 dm 行留在设置里，确认它在面板/校验里被判 `invalid-target` 且提示可读；改成 `userId` 后能订阅。
9. **`mentionOnly` 回归的可见变化**：一个原本“回全部消息”的群目标，打开 `mentionOnly` 后只回 @ 消息。

补验要求：只在测试群与自己的单聊上做；先备份 `stateDir`；记录 DSH/`dws` 版本、命令、脱敏输出；完成后在本文追加“真机结论”小节，并同步 README/CHANGELOG/兼容矩阵的措辞。

## 6. 已知限制

- **`contact user search` 形状只实测一次**：实现按别名容错（`userId`/`staffId`/`user_id`、`openDingTalkId`/`open_id` 等），但没有逐项真机核对。
- **`cid…=` 是形状判断**：正则是本地约定，不是服务端契约；极端情况下可能误拦合法的 `cid` 前缀 id，也可能放过服务端新增的形态。
- **`GET channel` 是进程内快照**：不清理 `orphaned`、不持久化 `lastError`，重启清零；同一 `targetId` 多行共享同一状态。
- **`retry_after_seconds` 只认数字秒**：字符串或其它单位按无提示处理，仍走本地指数退避。
- **停止重启是取舍**：连续 3 次拒绝后需要人工重试；换来的是真实原因不被退出噪音覆盖。
- **假 `dws` 夹具的保真度**：`tests/fixtures/fake-dws.mjs` 按我们对 `dws` 的理解构造输出，它证明的是“实现符合我们的契约模型”，不是“服务端一定这样返回”。
