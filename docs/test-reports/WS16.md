## 4. 覆盖缺口

1. **没有真机**：所有证据来自单测与假 `dws` 夹具；未在真实钉钉账号上触发“长引用 + 失败重试”。真实来源标题长度、真实模型重试后的第二稿差异未实测。
2. **`model_error` 没有端到端重试用例**：`pipeline-chat` 的重试用例只覆盖 `empty` 与 `sanitized_empty`；`model_error` 只由 `isRetryableComposeFailure` 真值表间接覆盖。`timeout`/`echoes_system_prompt` 的“不重试”同样只有真值表与代码路径，没有端到端用例。
3. **重试没有独立审计事件**：`decisions.attempts` 会 +1、host 日志有 `compose retry 1/1`，但审计流没有“重试发生”的事件；排障需要看日志。
4. **引用取舍是静默的**：`trimmed`/`dropped` 在聊天里只表现为“少了几条参考”，没有面向主人的提示；`SanitizeResult.citations` 目前只给代码与测试用。
5. **没有新增浏览器截图**：本版只多一个布尔字段，面板行为由字段表与 locale 契约测试覆盖；`reply.autoRetry` 的开关渲染未单独做组件测试。
6. **未测 `attempts` 的持久化边界**：重试计数随 Decision 落库，但“重试中途进程崩溃后是否会再次重试”没有专门用例（依赖 effect 队列的既有恢复语义）。
