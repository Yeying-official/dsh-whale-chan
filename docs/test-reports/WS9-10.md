## 1. 验收步骤与结果

### WS9 · 目标预建与共享工作区

1. 在「目标」页启用测试群目标（类型 `group`，显式 `openConversationId`），保存。
2. 读取 `GET /whale-chan/api/targets`：该目标出现只读 `workspace` 投影，`mode="ready"`，`path` 形如
   `<stateDir>\workspaces\conversation-<hash>`（`<hash>` 为 threadKey 的 SHA-256 前 16 位，本文不复述完整值）。
3. 确认该路径在磁盘上存在，且 DSH workspace registry 有同 path 记录，标题为 `钉钉 · <测试群名>`。
4. 触发一次群内 @（T3），回复由 `whale-reply-…` 会话产出；再批准一个任务（T4），worker 会话为 `whale-task-…`。
5. 在 DSH 中核对两个会话的 `sessionIds` 指向同一个 workspace，即步骤 2 的 `conversation-<hash>` 目录。
6. 任务在会话工作区内写入 `ws-check.txt`，内容为 `workspace-ok`；该目录即回复会话与任务的同一 workspace。

### WS10 · 目标页只读工作区与显示名

1. 目标页新增「工作区」区块：`ready` 的目标显示具体目录、「已创建」徽标与「复制路径」按钮。
2. `@我` 与 `open:` 单聊目标没有单一会话，显示「按会话创建」且路径为空（`per-conversation`），不误导为已建目录。
3. 该区块只读：没有新建、改名或删除入口。
4. 侧栏、插件列表与面板标题显示「DSH助理」；人设页仍显示默认人设「鲸鱼酱」，改名能力不变。

### 标题修复

任务加入已有会话目录时曾把标题改成 `任务 · <任务标题>`。本版修复后：

- 任务会话加入时使用会话标题（`钉钉 · <名>`），不再覆盖；
- 目标预建会校正已存在记录的标题；
- 复验结果为 `钉钉 · <测试群名>`。

## 2. 与旧版本的行为差异

| 项                    | v0.1.0                         | v0.2.0                                             |
| --------------------- | ------------------------------ | -------------------------------------------------- |
| 回复器工作区          | `<stateDir>/workspace`（共用） | 该会话的 `conversation-<digest>`                   |
| 任务默认工作区        | `tasks/<taskId>`               | 所属会话的 `conversation-<digest>`                 |
| 回复器会话 id         | 布局 v1                        | 布局 v2（会话 id 的哈希输入含 `<threadKey>\0v2`）  |
| `tasks.workspaceRoot` | 每个任务一个子目录的根         | 回复与任务共用的根                                 |
| 目标页                | 无工作区展示                   | 只读「工作区」区块（`ready` / `per-conversation`） |
| 显示名                | 「鲸鱼酱」                     | 「DSH助理」（默认人设仍为鲸鱼酱）                  |

## 3. 未覆盖与说明
